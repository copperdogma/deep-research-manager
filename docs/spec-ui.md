# Deep Research Manager — Product Spec
**Version:** 0.2  
**Date:** 2026-02-13  
**Author:** Cam (CineForge) + Claude  
**Status:** Ready for implementation

---

## Problem

Running multi-model deep research is high-value but high-friction. The actual AI interactions (pasting prompts, waiting for results) are fine. The pain is everything around them: getting an AI to write good prompts, formatting output files with proper metadata headers, naming files consistently, organizing them into a project folder. The friction is enough that research cycles don't happen when they should.

## Solution

A single-file web app that manages the **data lifecycle** of a deep research cycle: collecting prompts and outputs, formatting them as clean markdown with metadata, and exporting everything as a ready-to-use zip. No AI calls in the MVP — just structured data management. AI automation can be layered in later via optional API keys.

## Architecture Decisions

- **Single HTML file.** No build step, no framework, no server, no hosting. Open from disk or serve from anywhere. Maximum durability.
- **No backend.** All logic runs client-side. Zip generation via JSZip (CDN or inlined).
- **localStorage persistence.** Auto-save on every input change. Survive browser crashes, tab closures, multi-day research cycles. Support multiple concurrent research cycles.
- **No API keys required for MVP.** The app is a formatting and filing tool. API-powered automation is a future enhancement, not a dependency.
- **Model auto-detection.** Research reports include a structured metadata block (generated by the research prompt). The app parses this to auto-populate model name, slug, and filename. No manual model selection needed.

## Canonical Model Metadata Block

The research prompt (generated by the Claude Project) instructs every research model to begin its output with a structured metadata block:

```yaml
---
canonical-model-name: "{model's self-identified name, e.g., chatgpt-5.2-deep-research}"
report-date: "{ISO 8601 date}"
research-topic: "{topic as understood by the model}"
---
```

The app parses this block from pasted output to:
- Auto-populate the model name display
- Auto-generate the file slug (from `canonical-model-name`)
- Auto-set the filename (e.g., `chatgpt-5.2-deep-research-report.md`)
- Auto-record the report date

If the metadata block is missing or malformed, the app falls back to manual entry: show a text input for model name and proceed normally. This makes the system resilient to models that ignore the instruction.

## User Workflow

### Pre-App: Prompt Generation (Step 1)

The user has a conversation with an AI (via the "Deep Research Prompt Generator" Claude Project) to generate:
1. A **research prompt** to distribute identically to all deep research models
2. A **synthesis prompt** for a final AI to combine all model outputs into one report

This step stays outside the app for MVP. The app receives these prompts as text input.

## UI Layout

Single page, vertically scrolling, with clear phase separation.

### Header
- App title: "Deep Research Manager"
- Research cycle selector dropdown (for switching between saved cycles)
- "New Cycle" button
- "Delete Cycle" button (with confirmation)

### Phase 1: Setup
- **Topic/Title** — text input. On change, auto-generates a slug for the folder name (editable).
- **Research Prompt** — large textarea. "Copy to Clipboard" button beside it.
- **Synthesis Prompt** — large textarea. "Copy to Clipboard" button beside it.

### Phase 2: Collect Outputs
- **"Copy Research Prompt"** button (prominent, since the user will click this before pasting into each model)
- **"Add Report"** button — appends a new report card
- Each report card contains:
  - **Model name** — auto-populated from parsed metadata block, or editable text input if parsing fails
  - **File slug** — auto-generated from model name, editable
  - Large textarea for pasting raw output (metadata block + report body)
  - Character/word count indicator
  - Timestamp — auto-extracted from metadata block, or auto-set on paste
  - Status indicator: empty / parsed / manual-entry-needed
  - "Remove" button (with confirmation if content exists)
- Reports are displayed in the order added. No fixed number — add as many as needed.
- **"Download Individual Reports"** button — downloads each non-empty report as a separate .md file

### Phase 3: Synthesize
- **"Copy Synthesis Prompt + Reports"** button
  - Assembles: synthesis prompt text, then each model report (with model name header), into one clipboard payload
  - If total exceeds ~200K characters, warn the user and suggest attaching as files instead
  - Show a toast/notification confirming copy
- **Final Synthesis Report** — large textarea for pasting the synthesis output
  - App auto-parses metadata block (to capture which model did the synthesis)
  - If no metadata block: show text input for synthesis model name
- Timestamp auto-set on paste

### Phase 4: Export
- **"Download All as Zip"** button
  - Generates a zip file named `{topic-slug}.zip`
  - Contains a folder `{topic-slug}/` with all files (see File Format section)
- **"Download All as Individual Files"** button (alternative for people who don't want to unzip)

### Footer
- localStorage usage indicator (e.g., "3 cycles saved, ~245 KB")
- "Export All Cycles as JSON" button (backup)
- "Import Cycles from JSON" button (restore)
- Version number

## Metadata Block Parsing

When the user pastes content into a report textarea, the app immediately scans for a YAML frontmatter block:

```
---
canonical-model-name: "some-model-name"
report-date: "2026-02-13"
research-topic: "some topic"
---
```

**Parsing rules:**
- Look for content between the first `---` and second `---` at the start of the pasted text
- Extract `canonical-model-name` → set as model name, generate slug
- Extract `report-date` → set as timestamp
- Extract `research-topic` → display but don't override the cycle's title
- The metadata block is **preserved in the raw output** (not stripped) so the downloaded .md file retains it
- If no valid frontmatter found: highlight the model name field and prompt the user to enter it manually
- If frontmatter is found but `canonical-model-name` is missing: same fallback

**Slug generation from canonical-model-name:**
- Already expected to be lowercase-hyphenated (e.g., `chatgpt-5.2-deep-research`)
- Append `-report` for the filename: `chatgpt-5.2-deep-research-report.md`
- If duplicate slug exists in the same cycle, append `-2`, `-3`, etc.

## File Format

All output files are markdown with a YAML frontmatter metadata header.

### research-prompt.md
```markdown
---
type: research-prompt
topic: "{topic title}"
created: "2026-02-13T14:00:00-07:00"
---

# Research Prompt: {topic title}

{research prompt text}
```

### synthesis-prompt.md
```markdown
---
type: synthesis-prompt
topic: "{topic title}"
created: "2026-02-13T14:00:00-07:00"
---

# Synthesis Prompt: {topic title}

{synthesis prompt text}
```

### {model-slug}-report.md

The file content is the **raw pasted output as-is** (which already includes the model's own metadata block and report body). The app wraps it with an additional outer metadata header:

```markdown
---
type: research-report
topic: "{topic title}"
canonical-model-name: "{parsed from output}"
collected: "2026-02-13T14:32:00-07:00"
---

{raw model output, including its own --- metadata block --- and full report}
```

Note: this means the file will have two YAML frontmatter blocks — the app's outer envelope and the model's self-reported block inside the content. This is intentional: the outer block is the app's filing metadata, the inner block is the model's self-identification. Standard YAML frontmatter parsers will read the first (outer) block, which is correct behavior.

### final-synthesis.md
```markdown
---
type: synthesis-report
topic: "{topic title}"
synthesis-model: "{parsed from output or manually entered}"
source-reports:
  - "{model-1-canonical-name}"
  - "{model-2-canonical-name}"
  - "{model-3-canonical-name}"
synthesized: "2026-02-13T16:45:00-07:00"
---

{raw synthesis output, including its own --- metadata block --- if present}
```

## Data Model (localStorage)

```typescript
interface ResearchCycle {
  id: string;                    // UUID
  title: string;                 // e.g., "Long Document AI Editing for CineForge"
  slug: string;                  // e.g., "long-doc-ai-editing"
  createdAt: string;             // ISO 8601
  updatedAt: string;             // ISO 8601
  researchPrompt: string;
  synthesisPrompt: string;
  reports: Report[];             // dynamic list, any number
  finalSynthesis: {
    content: string;
    model: string;               // parsed or manually entered
    collectedAt: string | null;
  };
}

interface Report {
  id: string;                    // UUID
  canonicalModelName: string;    // parsed from output or manually entered
  slug: string;                  // auto-generated from canonicalModelName
  output: string;                // raw pasted output (including metadata block)
  collectedAt: string | null;    // parsed from output or auto-set on paste
  metadataParsed: boolean;       // whether auto-parsing succeeded
}
```

Storage key: `deep-research-cycles`  
Value: `JSON.stringify(ResearchCycle[])`  
Auto-save: debounced (500ms) on any input change.

## Behaviors & Edge Cases

### Auto-save
- Debounce 500ms after any input change
- Visual indicator: small "Saved" / "Saving..." text near header
- On page load, restore last-active cycle

### Slug generation (topic)
- Lowercase, replace spaces and special chars with hyphens, collapse multiple hyphens, trim leading/trailing hyphens
- Max 50 characters
- User can override

### "Copy Synthesis Prompt + Reports" assembly
Format:
```
{synthesis prompt text}

---

## Source Reports

### Report 1: {model-1-canonical-name}

{model-1-output, with its metadata block stripped for cleaner reading}

---

### Report 2: {model-2-canonical-name}

{model-2-output, metadata block stripped}

---

(etc.)
```

Note: strip the model's own `---` metadata block from the assembled copy-paste payload to avoid confusing the synthesis AI with YAML frontmatter. The raw output in localStorage and in downloaded files retains the metadata block.

If assembled text exceeds 200,000 characters, show a warning: "Total content is {n} characters (~{Math.round(n/4)}K tokens). You may need to attach reports as files instead of pasting inline." Still allow copy.

### Empty state handling
- "Download Individual Reports" — skip reports with no output; if all empty, disable button
- "Download All as Zip" — include only non-empty items; always include prompts if they exist; warn if no reports collected
- "Copy Synthesis Prompt + Reports" — warn if synthesis prompt is empty; warn if no reports collected

### Multiple cycles
- Cycle selector shows title + date created
- Switching cycles saves current state first
- New cycle starts with empty state (no preset model list)
- Delete cycle requires typing the cycle title to confirm (prevent accidents)

### Report ordering
- Reports display in the order added
- Optional: drag-to-reorder (nice-to-have, not required for MVP)
- In the zip file, reports are named by model slug, not by order

## Visual Design Notes

- Dark theme (the user will be staring at this during long research sessions)
- Monospace font for textareas (content is markdown/code-adjacent)
- Clear visual phases — the user should always know "where they are" in the workflow
- Generous textarea sizes — these will hold 10K+ character pastes
- Subtle progress indicator showing which phases have content (e.g., dots or checkmarks: Setup ✓ → Collect ◐ → Synthesize ○ → Export ○)
- Toast notifications for clipboard operations
- When metadata auto-parsing succeeds, brief visual confirmation (e.g., model name field flashes green and auto-fills)
- When metadata parsing fails, model name field highlights with a prompt to enter manually
- No unnecessary animations or flourishes — this is a utility tool

## Technology

- **Single HTML file** with inline CSS and JS
- **JSZip** (loaded from CDN: `https://cdnjs.cloudflare.com/ajax/libs/jszip/3.10.1/jszip.min.js`) for zip generation
- **No framework.** Vanilla JS with DOM manipulation. The app state is simple enough that React/Vue add complexity without proportional benefit.
- **No build step.** The file is the app.

## Future Enhancements (Not in MVP)

These are explicitly out of scope for the first build but should not be precluded by architectural choices:

1. **Optional OpenAI API key field.** When present, enable:
   - "Auto-generate prompts" button in Phase 1 (calls API with a meta-prompt to produce research + synthesis prompts)
   - "Auto-synthesize" button in Phase 3 (sends synthesis prompt + all reports to API, streams result back)
2. **Optional API keys for other providers.** When present, enable:
   - "Run research" button per report slot that sends the research prompt to that provider's API and streams the result directly into the textarea
   - This would make the entire workflow single-click: enter topic → generate prompts → run all models → synthesize → download
3. **Template library for research prompts.** Save reusable prompt templates that can be selected instead of writing from scratch.
4. **Diff view for comparing model outputs.** Side-by-side or inline diff of any two model reports to quickly spot agreements and contradictions.
5. **Project Agent integration.** Push output directly into a project document via MCP project tools instead of downloading a zip.
6. **Electron/Tauri wrapper.** For filesystem access without zip/download friction — write directly to a project folder.

## Acceptance Criteria

The MVP is done when:

- [ ] User can create a research cycle with a title and two prompts
- [ ] User can add any number of report slots (no preset model list)
- [ ] Pasting output into a report slot auto-parses the metadata block and populates model name, slug, and timestamp
- [ ] If metadata parsing fails, user can manually enter model name
- [ ] "Copy to Clipboard" works for research prompt and synthesis prompt
- [ ] "Copy Synthesis Prompt + Reports" assembles the full payload (with metadata blocks stripped from reports) and copies to clipboard
- [ ] "Download Individual Reports" produces correctly formatted .md files named by model slug
- [ ] "Download All as Zip" produces a zip with correctly named folder and all files with proper metadata headers
- [ ] All state persists in localStorage across page reloads
- [ ] Multiple research cycles can coexist and be switched between
- [ ] Cycles can be exported/imported as JSON for backup
- [ ] The app works offline (after initial CDN load of JSZip, or with JSZip inlined)
- [ ] Dark theme, readable, utilitarian
